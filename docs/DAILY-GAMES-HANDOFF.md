# Daily games handoff for Codex and Claude

This is a private testing project for two friends who want to play the same daily puzzles, compare scores, and keep their history. The owner reports developer permission to use the originals for this project. Commit and push finished work: pushing to main deploys to sfjc.dev. Keep publisher-provided files outside tracked paths unless their permission also covers public redistribution.

## Division of work

**Codex owns exact publisher fetching for every game.** Write and verify the dated loader, historical importer and publisher-specific parsing. Preserve edition IDs, dates, ordering, media references, accepted answers, and scoring or format versions. Return the publisher’s edition identity alongside the requested Pacific day. Verify a sample from the earliest available day, a recent day and a repeat or missing day where applicable. Record actual coverage and gaps. Supply one runnable refresh command and a fixture that can be replayed offline. Reuse working loaders and archives. Claude schedules and monitors these loaders in the site framework.

**Codex owns the original presentation and its source materials.** For each supported publisher format, deliver the exact puzzle format, controls and their states, button labels and placement, fonts, theme colors, icons, illustrations, audio and original exports. Capture mobile and desktop references for opening, playing, errors, reveals, winning, losing and sharing. Record animation triggers, duration, delay, easing and sequence. Supply reusable assets, CSS, keyframes or a small renderer for the parts that require exact reproduction. Where the source is unavailable, identify the specific missing item and keep fidelity open. The owner reports permission for private testing.

**Claude owns the rest of the implementation.** Build native players around the Codex materials, implement gameplay and deterministic score replay, hook up the daily shell, run scheduled imports, save snapshots, handle retries, build archives, friend boards, stats, sync, history and exports. Claude owns accessibility, responsive layout, reduced motion, tests, maintenance and release verification. Use the [game playbook](GAME-PLAYBOOK.md) and [daily games notes](DAILY-GAMES.md). Claude should do the initial inventory and run comparisons; return a narrowly identified source or fidelity discrepancy to Codex only when needed.

**Work order.** Start Kabloom first. In parallel Claude can test and integrate the existing Orbs, Chainle and Headcount assets. Reuse source materials across editions of the same format. A handoff includes the loader, fixtures, original visual and motion references, expected score on a perfect and imperfect run, and a sample share result. Claude records which checks actually passed.

## Completion checks for each game

1. Open a known date on phone and desktop. Compare the prompt, option order, assets, interactions, feedback, score and share output to the original. Record the exact edition used for comparison.
2. Play as two different friends. Verify independent progress and a common puzzle. Finish on one device, reopen under the same identity on another, and check the moves, score, stats and export.
3. Test an older edition, a missing edition and a day boundary. A retry must preserve the original dated snapshot and the first ranked result. An upstream outage must never silently assign a different puzzle to the date.
4. Exercise an invalid move and a forged client score. Verify that the server computes the score from legal moves. Compare original and local results on a perfect run and at least one imperfect run.
5. Mark a game complete only after native play and both sets of checks pass. A publisher link, embedded page, imported share text or downloaded puzzle bank is an intermediate deliverable.

## Local source handoff

Run the source intake from the repository root with Node and the installed project dependencies.
Use a publisher-provided export or an explicitly authorized HTTPS endpoint for each game. Each
edition is stored in `.publisher-editions/<game>/<source-date>.json`. Git and Vercel ignore this
directory. The first capture for a date is retained and a changed response fails instead of
overwriting the archive.

```sh
# One publisher date from a licensed feed
node --env-file-if-exists=.env.local --import tsx scripts/publisher-editions.ts refresh kabloom YYYY-MM-DD
# Historical range from the same feed. Missing dates are reported individually.
node --env-file-if-exists=.env.local --import tsx scripts/publisher-editions.ts archive kabloom FIRST_DATE LAST_DATE
# Capture an edition from an existing public source. Also accepts chainle or headcount.
node --import tsx scripts/publisher-editions.ts capture orbs 2026-04-29
# Import and replay the synthetic format fixture without credentials
node --import tsx scripts/publisher-editions.ts import kabloom 2000-01-01 tests/fixtures/publisher/kabloom-synthetic.json
node --import tsx scripts/publisher-editions.ts verify kabloom 2000-01-01 1999-12-31
```

Set `PUBLISHER_KABLOOM_FEED_URL` and, when issued by the publisher,
`PUBLISHER_KABLOOM_FEED_TOKEN`. The client sends the exact source date as the `date` query
parameter. Other games use the same variable pattern with their identifier in uppercase and
hyphens replaced by underscores. These are private-tool variables. For example, the site's
existing authorized crossword feed uses `CROSSWORD_DAILY_FEED_URL` separately.

The intake expects `publisher-edition/v1` with `game`, `editionId`, `sourceDate`, `sourceUrl` and
`payload`, plus optional `scoringVersion` and `originalDate`. The payload retains order and all
supplied fields, including media references. An optional Pacific play day is a separate value
returned by the offline reader. Use the date printed by the publisher as the archive key. Do
not substitute the most recent publisher date if the requested date is missing. A feed that
supplies its own envelope requires a source adapter before it will pass this intake.
